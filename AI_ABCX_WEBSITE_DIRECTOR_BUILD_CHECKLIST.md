## 1. Website Director Mission

Website Director is the web infrastructure and website control lane of AI-ABCX.

Its job is to:

- determine whether the business already has a usable website path
- classify whether the current site is missing, weak, acceptable, or strong
- decide whether AI-ABCX should connect to the existing site or replace it with AI-ABCX infrastructure
- support lead capture, intake, advertising landing, and operating handoff requirements
- keep the website compatible with the rest of the AI-ABCX system
- provide monitoring and visibility around site readiness and website performance
- preserve expansion paths into higher automation levels

It should not behave like a generic website builder.

It should behave like a corporate website operating layer under President control.

---

## 2. Website Director Launch Standard

Website Director is launch-ready only when it can do all of the following:

1. classify whether a business has no website, a weak website, or a usable website
2. support both hosted mode and connector mode
3. explain clearly why the recommended website path was chosen
4. support A / B / C levels clearly
5. collect enough information to create or configure the site path properly
6. show preview / approval before activation
7. surface website monitoring and status visibly inside AI-ABCX
8. integrate credibly with marketing, advertising, lead capture, call handling, and estimating

If one of those is missing, the director is not complete.

## 3. Canonical Role Definition

## Public-facing name

`Website Director`

## Internal role meaning

The AI-ABCX director responsible for website readiness, website analysis, AI-ABCX website generation, website connection logic, intake infrastructure, web-based lead capture compatibility, and long-term web control.

## Executive owner

`CMO`

Website Director belongs to the marketing and growth lane because the site is one of the main public surfaces through which demand enters the company.

It also acts as an infrastructure-control layer because many other directors depend on what the website can or cannot support.

Website Director should promise this:

- a website path that matches the actual business
- better website readiness for growth
- lead capture that fits the system
- clearer infrastructure for marketing and advertising
- cleaner intake compatibility
- easier future upgrades into more connected automation
- stronger President visibility around whether the company website is helping or blocking growth

Website Director should not promise only “we can build you a website.”

It should promise:

- infrastructure
- compatibility
- visibility
- lead readiness
- growth control

Based on Wix, Squarespace, Webflow, WordPress, GoHighLevel Website Builder, and QuoteIQ AI Website Builder, Website Director must match the market on:

- business-specific website creation
- mobile-ready page output
- service page support
- contact and intake forms

## 6. Where AI-ABCX Can Beat the Market

Website Director can beat outside tools in these areas:

- it can analyze an existing website instead of assuming a rebuild is always required
- it can support two commercial modes:
  - connector mode for an outside site
  - hosted mode for an AI-ABCX-managed site
- it can decide whether a business can stay at level A on the current website or needs deeper AI-ABCX website infrastructure for B / C
- it can connect website logic to marketing, advertising, lead capture, call handling, and estimating
- it can generate a business-specific site from guided activation answers
- it can support:
  - logo generation
  - style direction selection
  - generic content fallback
  - generic image fallback
  - intake infrastructure needed by the system
- if AI-ABCX hosts the site, the website becomes part of the operating system instead of a disconnected outside asset

This is the core differentiation.

AI-ABCX is not only “a website builder.”

It is a President-controlled website operating lane.

## 7. A / B / C Definition Draft

This checklist assumes these working level definitions.

They can be refined later, but implementation should move around this structure.

### Level A

- website connection / basic monitoring layer
- enough to support simpler system paths
- can work with an acceptable current website
- supports website visibility, basic intake compatibility, and site-health awareness

### Level B

- stronger website integration requirements
- improved lead and marketing support
- improved intake support
- stronger control over page structure and conversion surfaces
- can use AI-ABCX website infrastructure when needed

### Level C

- highest readiness for deep AI-ABCX integration
- strongest hosted-site path when required
- richer marketing, advertising, intake, and operating integration
- built to support the strongest connected system paths

## 8. Required Website Modes

Website Director must support two operating modes.

### Mode 1: Connector Mode

Purpose:

- keep the client's current website
- connect AI-ABCX functionality to it where possible
- monitor whether the current site is enough for the selected system level

Required visibility:

- current site URL
- current site classification
- allowed system level on existing site
- blockers or limitations caused by the current site

### Mode 2: Hosted Mode

Purpose:

- create and run an AI-ABCX-controlled website path
- support the business with AI-ABCX-native intake, lead capture, and growth infrastructure
- preserve tighter compatibility with higher-level automation

Required visibility:

- selected style direction
- generated site structure
- preview state
- approval state
- publish / activation state

Optional later-state refinement can be added after launch, but these are the minimum states needed for credible recommendation logic.

## 10. Required Product Surfaces

Website Director should not launch as hidden backend logic only.

It needs visible product surfaces.

### Surface 1: Website Analysis Result Surface

Purpose:

- show whether the business has no site, a weak site, or a usable site
- explain what the site is missing
- explain what the system needs from the site

Required visibility:

- current URL
- website status
- summary explanation
- recommended path

### Surface 2: Hosted vs Connector Mode Surface

Purpose:

- show whether AI-ABCX is connecting to the current site or recommending a new hosted site
- explain the operational difference clearly

Required visibility:

- mode type
- reason for mode
- level limitations if current site remains
- level opportunities if hosted path is used

### Surface 3: Website Intake Form

Purpose:

- collect all information required to generate or configure the website path

Required inputs:

- business name
- website URL if present
- services
- service area
- phone and contact path
- logo
- content readiness
- photo readiness
- color / style direction

### Surface 4: Preview / Approval Surface

Purpose:

- show what AI-ABCX is preparing before activation
- let the client approve the website direction

Required visibility:

- homepage preview
- service section preview
- intake / lead capture preview
- style preview
- approval state

### Surface 5: Website Monitoring / Statistics Surface

Purpose:

- show whether the website is healthy and usable for the system
- give the President visibility into the website lane

Required visibility:

- website mode
- website status
- lead capture readiness
- intake readiness
- compatibility notes

## 13. Required Director Handoffs

Website Director is one of the strongest dependency directors in the system.

It must explicitly define handoffs with:

- `Marketing Director`
- `Advertising Director`
- `Lead Generation Director`
- `Call Handling Director`
- `Estimator Director`

### Marketing Director handoff

- website has to support campaign landing and lead capture
- Website Director must show whether the current site can support marketing upgrades

### Advertising Director handoff

- ads need a credible landing destination
- Website Director must show whether the current site can receive and convert paid traffic properly

### Lead Generation Director handoff

- website forms and conversion paths affect lead quality
- Website Director must expose whether the intake path is strong enough

### Call Handling Director handoff

- website and call paths often work together
- Website Director must support web-based contact and after-hours continuity paths

### Estimator Director handoff

- quote requests may begin from website forms or estimate request surfaces
- Website Director must support estimate-compatible intake where required

## 14. Guided Activation Requirements

Step 1 must learn:

- whether they already have a website
- what URL it uses if present
- whether they believe the current site performs well
- whether they need the website mainly for:
  - credibility
  - lead capture
  - intake
  - marketing support
  - advertising traffic
  - estimate requests
- whether they want a new AI-ABCX-managed website
- whether they already have:
  - logo
  - brand colors
  - written content
  - service photos
- what style direction they prefer

Step 2 recommendation must explain:

- whether the current site is enough
- whether AI-ABCX hosted website infrastructure is recommended
- what Website Director level is recommended
- whether the current site limits upgrades
- why the recommendation affects the rest of the system

Step 3 activation must support:

- preview review
- approval state
- final selected website path
- visible explanation of what is included

## 15. Pricing Decisions Required

Before Website Director is commercially finished, the following pricing questions must be resolved:

- hosted mode pricing for A / B / C
- connector mode pricing for A / B / C
- whether basic monitoring is included at every level
- whether hosted website path includes infrastructure by default
- how upgrades from connector to hosted mode are priced
- how upgrades from A to B to C are priced
- what happens if the current site is not sufficient for the selected system path

Current pricing discussions suggest the need for two families:

- AI-ABCX-managed website path
- client-owned website connector path

That split should be preserved in final pricing logic.

## 17. Internal Test Scenarios

These scenarios should exist before Website Director is considered real.

### Test 1: No-website path

- business has no site
- system recommends hosted AI-ABCX path
- recommendation explains why

### Test 2: Weak current website path

- business has a current site
- system classifies it as weak
- system explains what is missing
- recommendation shows why hosted path is stronger

### Test 3: Acceptable current website path

- business has a usable site
- system allows connector path
- A-level configuration remains possible

### Test 4: Upgrade blocked by current site

- business wants higher-level web-connected functionality
- current site is not sufficient
- system explains why hosted path is required

### Test 5: Hosted website generation path

- business provides no content or photos
- system uses generic fallback path
- preview still remains coherent

### Test 6: Style direction path

- business selects a style direction
- preview reflects the chosen direction visibly

### Test 7: Website + marketing path

- marketing is selected
- Website Director explains whether the site path can support it

### Test 8: Website + call handling + lead capture path

- website, calls, and lead capture are all needed
- website path supports one connected operating flow
