# AI-ABCX Launch Module And Level List

This document defines the recommended first-launch list of:

- modules
- A-level launch availability
- later B and C automation expansion
- launch bundles
- deferred combinations

It is based on the current AI-ABCX strategy:

- modular corporate management system
- `A / B / C / X` as automation levels
- field service as the first launch market

---

## 1. Launch Position

The first launch should be presented as:

`the first live implementation of the AI-ABCX corporate automation system for field service businesses`

Clients may enter through selected modules, but the launch should stay disciplined.

That means:

- not every module is available at launch
- only A-level modules are available at launch
- not every module combination is available at launch

---

## 2. Recommended First-Launch Modules

These are the modules that make the most sense to support first.

| Module | Launch Recommendation | Why |
|---|---|---|
| President Core | Yes | The whole system needs the President-led identity and top-level command layer. |
| CRM | Yes | This is the backbone required for all other modules. |
| Call Handling | Yes | Strong flagship entry point and core business-action engine. |
| Dispatcher | Yes | High-value field-service control module and major adoption path. |
| Closeout | Yes | Required for disciplined business outcome and payment truth. |
| President Follow-Up | Yes | Keeps unresolved business alive and supports management value. |
| Performance Intelligence | Yes | Core conversion, justification, and monthly executive-improvement layer. |
| Marketing | Strategic yes, if intentionally prioritized | Very high-value entry module, but requires stronger CRM depth and broader launch scope. |

## 3. Recommended First Available Automation Level By Module

The first launch should start with `A` level only across active modules.

Recommended release rule:

- `Stage A` launch = A-level modules available
- `Stage B` release = B-level upgrades become available for extra charge
- `Stage C` release = C-level upgrades become available for extra charge
- `X` remains a later highest-level intelligent tier

| Module | First Launch Level | Near-Term Next Level | Later Levels |
|---|---|---|---|
| President Core | A | B | C, X |
| CRM | A | B | C, X |
| Call Handling | A | B | C, X |
| Dispatcher | A | B | C, X |
| Closeout | A | B | C, X |
| President Follow-Up | A | B | C, X |
| Performance Intelligence | A | B | C, X |
| Marketing | A | B | C, X |

## 4. Recommended Launch Meaning By Module

## 4.1 President Core A

Should include:

- President dashboard
- company structure visibility
- basic accountability view
- shared truth visibility across active modules

## 4.2 CRM A

Should include:

- shared lead/customer/job truth
- source tracking
- qualification tracking
- basic pipeline state
- scheduling-support fields
- outcome fields
- activity timeline

## 4.3 Call Handling A

Should include:

- AI inbound call handling
- caller identity capture
- call intent
- urgency
- qualification
- lead qualification
- transcript / recording linkage
- record creation in CRM

## 4.4 Dispatcher A

Should include:

- scheduling visibility
- assignment visibility
- manual or lightly assisted control
- confirmation pressure
- reroute / hold / reschedule visibility

## 4.5 Closeout A

Should include:

- outcome capture
- amount paid truth
- unresolved vs closed decision
- follow-up trigger

## 4.6 President Follow-Up A

Should include:

- unresolved opportunity tracking
- callback and estimate follow-up visibility
- next-step ownership
- follow-up reason tracking

## 4.7 Marketing A

If Marketing is included in first launch:

### Marketing A

- source visibility
- campaign structure
- basic lead-source truth
- referral/reactivation visibility

My recommendation:

- only include `Marketing` at launch if `Marketing A` is still strong enough to feel serious and useful
- deeper connected attribution and revenue intelligence move into `Marketing B` after Stage B release

## 4.8 Performance Intelligence A

Should include:

- initial Corporate Growth Investment Study
- basic investment-to-outcome estimate
- visible top revenue and profit leaks
- visible top improvement opportunities
- basic monthly study-update logic
- basic system-improvement recommendations tied to active modules

Recommendation:

- include `Performance Intelligence A` as core, not as an optional upgrade
- use `Performance Intelligence B/C/X` as paid depth expansion

## 6. Recommended Upgrade Paths After Launch

Clients should be able to expand in two ways.

### 6.1 Add more modules

Examples:

- President Core A -> add Call Handling A
- President Core A -> add Dispatcher A
- Growth Core -> add Closeout A

### 6.2 Upgrade automation level

Examples:

- Dispatcher A -> Dispatcher B
- CRM A -> CRM B
- Call Handling A -> Call Handling B
- Marketing A -> Marketing B after Stage B release
- Marketing B -> Marketing C after Stage C release

This creates a clear expansion ladder toward fuller ABCX adoption.

## 8. Recommended Deferred Automation Levels

For launch discipline:

- `A` should be the dominant starting level
- `B` should unlock only after Stage B release
- `C` should unlock only after Stage C release
- `X` should remain future roadmap and premium upgrade territory

Recommended first-launch restraint:

- avoid pretending most modules are already `C` or `X`
- let `A` form the real launch base

## 10. My Recommendation

If speed matters most:

- choose `Operations-First Launch`

If perceived value, broader appeal, and stronger market wedge matter more:

- choose `Bigger Growth + Operations Launch`

Based on the recent discussion, your current instinct seems closer to:

- `Bigger Growth + Operations Launch`

because Marketing may become one of the most demanded and margin-friendly flagship modules.

## 11. Launch Decision Checklist

Before locking the launch plan, we should answer:

1. Is Marketing included at first launch?
2. If yes, is `Marketing A` strong enough to justify launch inclusion?
3. Is President Core always included in every sale?
4. Is CRM always included in every sale?
5. Which bundles will be publicly sold at launch?

My recommendation:

- `President Core` should always be included
- `CRM` should always be included

That keeps the full corporate story intact.
