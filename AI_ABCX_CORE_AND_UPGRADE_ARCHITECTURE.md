# AI-ABCX Core And Upgrade Architecture

This document defines the working product architecture for `AI-ABCX`.

It exists to keep:

- stage definitions stable
- dashboard behavior aligned
- module decisions consistent
- upgrade decisions separate from core-stage logic

---

## Core Product Principle

`AI-ABCX` is the executive operating system for service businesses.

Its core purpose is to bring:

- corporate structure
- executive control
- accountability
- management visibility
- increasingly automated management logic

to small and medium sized service companies.

Core product line:

`AI-ABCX brings corporate structure to service businesses.`

`You lead as President.`

---

## Core Stage Model

The full company structure should be visible before public launch.

All major structure for `A`, `B`, and `C` should be built and internally tested before Stage A release.

Public release then happens in stages so real customer feedback can shape what opens next.

---

## Stage A

Stage A is the foundational operating structure.

It should provide:

- President dashboard as the top-level control surface
- visible full company structure
- core executive lanes where real business truth already exists
- operational visibility and control in the most important departments

Stage A is not meant to simulate full automation.

It should focus on:

- operations
- revenue
- executive synthesis
- financial truth at a lean level
- clear company structure

Stage A should feel:

- real
- controlled
- useful
- not overextended

---

## Stage B

Stage B is primarily the scheduling and operational depth expansion stage.

Its purpose is not to broadly unlock every future department.

Its purpose is to add:

- scheduling depth
- broader operational management structure
- expanded daily management control where Stage A already proved the need

Stage B should be understood as:

- broader operational control
- not a generic feature expansion layer

This means departments that do not truly activate in Stage B should not be described as if they do.

---

## Stage C

Stage C is the advanced management automation layer.

This is the most important defining rule.

Stage C is not simply “the stage where more departments appear.”

Stage C is the stage where the system becomes a much deeper management engine.

Stage C should include:

- advanced management control
- stronger oversight across the whole company
- automated or semi-automated management pressure
- recommendations and suggestions
- accountability with time frame expectations
- broader executive control across the company structure

Stage C specifically includes:

- rating executives
- rating directors
- rating systems
- rating people
- watching President performance
- management recommendations
- performance improvement guidance

Stage C should feel close to full management automation.

---

## Stage C People Management

People-management functions belong naturally inside Stage C core.

That means Stage C may include:

- `CHRO`
- relevant people-management directors
- workforce oversight
- people-performance visibility
- people ratings
- accountability at people-management level

This people layer can exist in the base system.

However:

- deeper HR workflow depth can still become a future upgrade module

So the distinction is:

- Stage C core includes people-management base function
- future HR upgrade may include advanced HR system depth

---

## Core Vs Upgrade Systems

The core `AI-ABCX` system should stay distinct from optional integrated systems.

This is important both for product clarity and for customer flexibility.

### Core system means:

- President dashboard
- executive structure
- department structure
- staged management activation
- advanced management automation by Stage C

### Optional systems mean:

- systems a customer may already have
- or systems they may want to buy from us

These should not be forced into the core just because they are useful.

---

## Marketing System

Marketing should not define Stage B.

Marketing also should not define Stage C.

Marketing may exist as:

- visible structure in earlier stages
- optional integrated system available later

If a customer already has their own marketing system:

- they can keep using it
- `AI-ABCX` still governs at executive level

If a customer does not have a marketing system:

- we can sell one as an upgrade

Recommended rule:

- marketing system is a separate optional system
- availability can begin at Stage C
- if parts are ready earlier internally, they still should not distort the meaning of Stage B

---

## Accounting System

Accounting follows the same architecture rule as marketing.

Some customers already have their own accounting setup.

Those customers should still be able to use `AI-ABCX` core.

Other customers may want to buy accounting capabilities from us.

So:

- core financial oversight can exist in the main system
- full accounting system depth can exist as optional upgrade
- optional accounting system can be offered when appropriate

Recommended rule:

- accounting system is a separate optional integrated system
- availability can begin at Stage C

---

## HR System

HR needs a split definition.

### Base Stage C people-management layer:

- belongs in core
- supports advanced management automation
- supports ratings and oversight
- supports people accountability

### Advanced HR module:

- future upgrade
- deeper HR process/system depth
- more specialized HR operational control

This keeps people management inside core Stage C while preserving room for a richer HR product later.

---

## External Vs Internal Systems

`AI-ABCX` should work whether a customer:

- uses our optional system
- uses an external system they already own
- or has no existing system and needs one from us

That means the executive operating system should not require customers to abandon their own tools.

Instead:

- core dashboard should be able to govern with external systems present
- optional modules can deepen integration when customers buy them from us

This is a product advantage, not a compromise.

---

## Dashboard Implication

The President dashboard should reflect the distinction between:

- core executive management
- stage-based activation
- optional systems
- future upgrade systems

It should not imply that every visible lane is fully active.

It also should not imply that every customer uses our internal version of every function.

Instead, dashboard behavior should clearly distinguish:

- active now
- limited now
- structurally visible
- future-stage
- optional upgrade
- external system compatible

---

## Current Working Rules

At the current state of product definition:

1. `Stage A` = foundational operating structure
2. `Stage B` = scheduling and operational depth expansion
3. `Stage C` = advanced management automation layer
4. ratings belong mainly to `Stage C`
5. people-management base belongs in `Stage C` core
6. marketing system should be treated as optional upgrade
7. accounting system should be treated as optional upgrade
8. advanced HR system can be treated as future upgrade
9. customers may use external marketing/accounting systems instead of ours

---

## Implementation Guidance

When editing live dashboards, preview dashboards, or stage maps:

- do not describe Stage B as if it activates marketing unless that is truly intended
- do not define Stage C by marketing
- define Stage C by advanced management automation
- keep optional systems clearly separate from stage definitions
- keep external system compatibility explicit in future architecture decisions

This file should be treated as the reference for future dashboard behavior and product-structure discussions.
