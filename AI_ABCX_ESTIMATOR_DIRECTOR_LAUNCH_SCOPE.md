# AI-ABCX Estimator Director Launch Scope

This document locks the launch scope for `Estimator Director`.

It is the authority for:

- what Estimator Director must do at launch
- what it does not need to do yet
- how `A / B / C` differ
- what counts as complete

This document is not:

- the pricing sheet
- the benchmark research file
- the file refactor map

It is the launch scope lock.

---

## 1. Product Position

`Estimator Director` is the quote-conversion director inside AI-ABCX.

Its job is to:

- capture estimate demand
- structure estimate preparation
- deliver customer-facing estimates
- track estimate decisions
- keep unresolved quote opportunities visible
- hand accepted or unresolved quotes into the next operating lane

Estimator Director is not just a quote tool.

It is a controlled corporate lane under President oversight.

---

## 2. Launch Rule

Estimator Director launches as a real working director on day one.

Important:

- `A / B / C` are capability levels
- `A / B / C` are not release phases
- `X` is not in launch scope now

Estimator Director must therefore be fully productized at launch for:

- Level A
- Level B
- Level C

---

## 3. Core Promise

At launch, Estimator Director must make this true:

- every quote request is visible
- every quote has a state
- every quote has a next action
- the President can see quote pressure clearly
- accepted quotes do not disappear
- unresolved quotes do not disappear
- follow-up and scheduling can receive clean handoff

---

## 4. What Estimator Director Must Do At Launch

### 4.1 Intake

Must accept estimate requests from:

- website
- AI call handling handoff
- manual internal entry
- ad / campaign source
- referral / direct source
- existing customer repeat request

Each request must capture:

- customer name
- phone
- email if available
- service type
- request notes
- source tag
- urgency

### 4.2 Estimate workflow

Must support these workflow states:

- `new_request`
- `intake_in_progress`
- `estimate_preparing`
- `estimate_sent`
- `waiting_on_customer`
- `revision_requested`
- `accepted`
- `follow_up_needed`
- `scheduled_after_acceptance`
- `lost`

Each state must show:

- current status
- timestamp
- current owner
- next action

### 4.3 Estimate formats

At launch, Estimator Director must support:

- standard estimate
- options estimate
- package estimate
- quick estimate

These are required launch features, not later ideas.

### 4.4 Customer-facing delivery

Estimator Director must deliver estimates by:

- text
- email
- direct link

Optional printable PDF can exist if already practical, but text / email / link are the minimum launch methods.

### 4.5 Customer decision handling

Estimator Director must handle:

- accepted
- no response
- revision requested
- lost

### 4.6 President visibility

President must be able to see:

- open quotes
- accepted quotes
- quotes waiting on customer
- revision pressure
- lost quotes
- follow-up pressure

### 4.7 Handoff

Estimator Director must be able to hand off into:

- Follow-Up Director
- Scheduling Director
- President review

---

## 5. What Estimator Director Does Not Need At Launch

These are intentionally out of launch scope unless they already exist cleanly and do not slow core delivery:

- advanced satellite measurement engine
- industry-specific pricebook automation by every trade
- advanced AI image generation tied to the quote
- deep finance / lending pathways
- full external CRM migration complexity
- complex multi-branch crew optimization
- fully autonomous quote negotiation
- Level X estimator logic

These may come later.

They are not required for Estimator Director to be launch-credible.

---

## 6. A / B / C Capability Levels

These are launch-level definitions, not phased release definitions.

### Level A

Level A is the clean, usable core estimator lane.

It includes:

- estimate request intake
- source tagging
- standard estimate
- basic quick estimate
- estimate sent tracking
- customer response tracking
- accepted / lost / follow-up state tracking
- President visibility
- handoff to follow-up / scheduling

Level A promise:

- no quote disappears
- owner can see quote truth
- team can move faster with basic structure

### Level B

Level B adds stronger estimate workflow depth.

It includes everything in A, plus:

- options estimate
- stronger revision workflow
- stronger quote preparation structure
- better follow-up alignment
- more visible quote accountability
- stronger internal estimate queue management

Level B promise:

- cleaner quote control
- better upsell and choice structure
- better conversion discipline

### Level C

Level C is the strongest estimator operating lane at launch.

It includes everything in B, plus:

- package estimate logic
- strongest source-aware quote handling
- strongest queue visibility
- strongest President-facing estimate pressure visibility
- strongest connected handoff logic
- strongest conversion-path discipline

Level C promise:

- estimator becomes a real corporate revenue lane, not just a faster quote tool

## 7. Independent vs Connected Selling

Estimator Director can sell independently.

It is one of the strongest independent entry directors because many businesses already understand the pain of:

- slow quotes
- lost quote requests
- weak follow-up
- poor quote visibility

But Estimator Director also becomes stronger when connected to:

- Call Handling Director
- Website Director
- Follow-Up Director
- Scheduling Director

That means:

- independent sale is allowed
- connected recommendation is encouraged

## 8. Minimum Competitive Standard

At launch, Estimator Director must be credible against the strongest outside estimator products.

It must at minimum match:

- fast estimate creation
- multiple estimate formats
- clean estimate delivery
- clear customer decision path
- visible estimate workflow

It should beat them by:

- President visibility
- connected follow-up
- connected scheduling handoff
- source-aware corporate workflow

## 9. Visual / UX Standard

The estimator dashboard must feel:

- active
- operational
- easy to scan
- quote-centered
- not over-explained
- not limited by old stage language

The main work area must visually prioritize:

- active quote
- queue needing action
- estimate outcome path
- next action

The top control area must not dominate the screen.
