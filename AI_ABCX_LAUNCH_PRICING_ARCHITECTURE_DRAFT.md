# AI-ABCX Launch Pricing Architecture Draft

This document is the working pricing architecture draft for `AI-ABCX`.

It does not lock the final public price list yet.

Its purpose is to define:

- how pricing should work
- what the customer is actually paying for
- which directors can be sold alone
- which directors need other directors
- where usage pricing is required
- how full-system offers fit into the modular model

---

## 1. Core Pricing Rule

`AI-ABCX` should be priced by functional director, not by abstract executive figure.

That means the customer is not charged for:

- `CEO`
- `COO`
- `CRO`
- `CFO`
- `CSO`
- `CPIO`
- `CMO`
- `CAO`

Those executives are the corporate structure and control logic of the system.

The customer is charged for:

- the actual directors they activate
- the level of each director (`A / B / C`)
- any usage-based layer where real variable cost exists
- any hosting / website infrastructure path where applicable
- any extra user seats where applicable

---

## 2. Customer-Facing Pricing Promise

The pricing system should feel clear, human, and predictable.

That means the public pricing message should be:

- no hidden costs
- no giant bundled plan full of functions they do not need
- no forced payment for unrelated modules
- clear monthly pricing per activated business function
- usage charges only where real variable cost exists

Recommended message:

`You only pay for the directors your business actually uses.`

`If you add more capability, your system grows with you.`

---

## 3. Permanent System Rule

Every valid customer setup still includes:

- `President Core`
- shared company record / system truth
- dashboard visibility
- future expansion ability

This means even a customer who buys only one director is still activating:

- an `AI-ABCX` system shell
- a `President Dashboard`
- a future-ready operating structure

Current working pricing assumption:

- `President Core` is not separately charged at launch
- the first paid director activates the system

---

## 4. Primary Price Components

There should be only four pricing component types.

### 1. Director Subscription

This is the main monthly charge.

Example:

- `Scheduling Director B = $X / month`

### 2. Usage-Based Charge

Only used where AI-ABCX has real marginal cost.

Best current example:

- `Call Handling Director`

### 3. Infrastructure Path Charge

Used where the business chooses an `AI-ABCX-owned` technical path versus an external connector path.

Best current example:

- `Website Director`

### 4. Seat Charge

Used only where user quantity materially changes system value or admin complexity.

This should affect:

- bigger teams
- multi-user management
- higher coordination layers

It should not be the main pricing logic.

- Estimator Director
- Call Handling Director

### Class C: Dependent Directors

## 6. Launch Pricing Logic By Level

The public meaning of `A / B / C` should also translate into pricing logic.

### Level A

Price intent:

- entry point
- clear value
- easier adoption
- lower automation depth

Commercial purpose:

- reduce friction
- let customers start small
- allow visible improvement without forcing a large commitment

### Level B

Price intent:

- stronger workflow connection
- more automation
- more coordination

Commercial purpose:

- best operational value for many growing businesses
- most likely upgrade path from A

### Level C

Price intent:

- highest automation depth
- strongest orchestration
- premium operational leverage

Commercial purpose:

- highest-value customers
- strongest expansion-minded customers
- strongest multi-director upsell path

## 7. Recommended Price Strategy By Director Type

This is the pricing architecture recommendation, not the final public price lock.

### Estimator Director

Strong benchmark pressure exists in this category.

Recommended direction:

- `A` = low-friction starter
- `B` = serious quoting workflow
- `C` = advanced quoting orchestration

Best pricing posture:

- aggressive enough to win entry adoption
- strong enough to signal professional value

Suggested draft range:

- `Estimator A`: `$29–39`
- `Estimator B`: `$59–79`
- `Estimator C`: `$99–149`

### Call Handling Director

This should use hybrid pricing:

- monthly director charge
- per-minute usage charge

Reason:

- clear customer understanding
- real variable cost exists
- easier than “AI credits”

Working launch logic:

- `A / B / C` controls capability depth
- minutes are billed transparently

Suggested launch direction:

- `Call Handling A`: `$99 / month + $0.15 / minute`
- `Call Handling B`: `$149 / month + $0.15 / minute`
- `Call Handling C`: `$249 / month + $0.15 / minute`

Future option:

- later increase minute rate
- keep launch pricing as a trust-building advantage

### Website Director

Website Director should use two commercial paths.

#### Connector Path

Customer keeps existing website.

Suggested direction:

- `Website A`: `$10 / month`
- `Website B`: `$15 / month`
- `Website C`: `$20 / month`

#### AI-ABCX Website Path

AI-ABCX creates, hosts, monitors, and controls the website as part of the system.

Suggested direction:

- `Website A`: `$29 / month`
- `Website B`: `$39 / month`
- `Website C`: `$49 / month`

This path should include:

- hosting
- system-compatible structure
- analytics / monitoring
- future module compatibility

### Follow-Up Director

Strong standalone value, but less infrastructure-heavy.

Suggested draft range:

- `Follow-Up A`: `$19–29`
- `Follow-Up B`: `$39–59`
- `Follow-Up C`: `$69–99`

### Scheduling Director

Can be standalone, but gains much more value when connected.

Suggested draft range:

- `Scheduling A`: `$29–39`
- `Scheduling B`: `$59–79`
- `Scheduling C`: `$99–149`

### Marketing Director

Higher variation in scope, but should still have visible level pricing.

Suggested draft range:

- `Marketing A`: `$29–49`
- `Marketing B`: `$79–129`
- `Marketing C`: `$149–249`

## 8. Working Rule For Full-System Offers

The modular structure should remain the default pricing logic.

But a `full-system recommendation` must still exist.

Reason:

- some businesses do need broad operational transformation
- some larger companies may want a near-complete configuration
- some expansion-minded owners may intentionally choose the stronger system

So the architecture should support three recommendation depths:

1. `Intent Fit`
2. `Improved Configuration`
3. `Advanced Configuration`

That means the customer can receive:

- a minimal valid configuration
- a stronger growth configuration
- a high-performance full-system recommendation

This does not break modular pricing.

It simply means:

- the advanced option is priced as the sum of many activated directors
- possibly with a multi-director bundle discount

---

## 9. Bundle Logic

Because AI-ABCX is modular, bundles should behave as pricing incentives, not as the main product logic.

Recommended bundle rule:

- the more directors activated, the lower the effective average price per director

This supports the user’s product direction:

- natural growth
- easier upsell
- flexible adoption
- no forced giant plan

Suggested discount structure:

- `1–2 directors`: standard list pricing
- `3–4 directors`: small bundle discount
- `5–7 directors`: stronger bundle discount
- `8+ directors`: advanced system discount

This discount should be shown clearly in system recommendations.

---

## 10. User Seat Logic

User quantity should affect pricing, but not overwhelm the module logic.

Recommended rule:

- `1 owner / president` should fit inside standard launch pricing
- small team use should be tolerated without heavy seat charges
- meaningful seat charges should begin only when multi-user operations become part of real value expansion

Good use case:

- office staff
- managers
- sales reps
- dispatchers
- field leads

Recommended seat approach:

- first small seat allowance included with qualifying configurations
- then a clear `per extra user` charge

This should be finalized after dashboard/user-role scope is locked.

---

## 11. Trial Architecture

Current preferred direction:

- standard public path does not promise a fully free unlimited system trial by default
- partner path can receive stronger guided trial treatment later

For now, pricing architecture should assume:

- free business analysis
- free custom configuration
- free feasibility / visibility summary
- optional guided proof flows

This keeps the system credible while reducing abuse.

---

## 12. What Must Be Avoided

Pricing should avoid:

- AI credits as the main public pricing language
- big confusing all-in-one bundles as the only option
- unclear hidden charges
- offering dependent directors as if they are strong standalone products
- forcing customers into full-system pricing when partial valid configurations exist
- underpricing advanced orchestration so much that the system looks weak

## 14. Final Working Position

Current best working pricing position:

- `AI-ABCX` is priced by activated director
- executives are structural, not separately billed
- `A / B / C` reflects operational depth
- standalone directors are the main entry path
- dependent directors are sold through valid combinations

- pricing should feel clear, human, and custom-made
