# AI Call Port Launch Plan

This document defines the actual launch plan for AI Call Port and the first implementation order.

It is not a brainstorm document.
It is the working launch definition.

## Launch Philosophy

AI Call Port is building more than a customer base.
It is building a customer base and a fan base at the same time.

This means the launch should be designed to create:

- trust
- participation
- transparency
- shared upside
- visible progress

Customers and partners should feel that helping AI Call Port improve also benefits them directly.

## Launch Decision

AI Call Port launches publicly through **Stage A: the AI Call Agent**.

This is the first live public product.

It should be presented as:

- a real public product
- the foundation module of the larger AI Call Port system
- available on its own
- expandable later through additional modules when a business needs them

AI Call Port is not launching first as the full system.
It is launching first through the strongest foundation module.

## What Launches In Stage A

Stage A includes:

- advanced inbound AI call handling
- conversation-category logic
- lead capture
- qualification
- routing / escalation
- after-hours handling
- emergency handling
- business-specific handling rules
- transcript and call visibility

Stage A is meant to be strong enough to stand as a real product by itself.

## What Is Excluded From Stage A

Stage A should not depend on:

- direct sales scheduling
- direct service scheduling

Those belong in a later expansion stage.

This keeps launch quality more controllable while still proving the real intelligence layer.

## Modular Expansion Structure

AI Call Port is modular.

Customers can:

- stay on the AI Call Agent only
- add scheduling later
- add deeper modules later

Customers should not be expected to guess what they need.

AI Call Port includes an analysis and configuration layer that determines:

- which modules are needed
- which logic categories matter most
- which routing and fallback rules should be active
- which upgrade path makes sense

## Customer Plans At Launch

Stage A launches with two customer tracks:

- Regular plan
- Partner plan

### Regular Plan

This is the standard public customer plan for Stage A.

Working price:

- `$499/month`

### Partner Plan

This is a structured collaboration plan for companies that are willing to participate more actively.

Working price:

- `$349/month`

Partner companies also receive:

- a personal referral link
- `$15` off their monthly payment for each referred active customer
- dashboard visibility into referral activity and earned monthly credits

The partner plan is not just a lower price.
It is a different operating relationship with defined benefits and responsibilities.

## Partner Responsibilities

Partner companies are expected to:

- provide consistent operational feedback
- respond to follow-up questions
- participate in periodic review/check-in conversations
- report failures, awkward moments, and business-specific edge cases
- help confirm what is working well
- participate in testimonial, review, quote, or case-study requests when results justify it

Partner pricing and benefits should only be activated after explicit agreement to the partner policy during activation.

## Public Positioning

AI Call Port should be positioned publicly as:

- a modular business operating system
- launched through its first live module: the AI Call Agent
- expandable later through additional modules

It should not be positioned as:

- just another AI receptionist
- or a vague future operating system that is not live yet

The public message should be:

- Stage A is live now
- it is a real product
- it is the first module of the larger system

The public tone should be communication-first, not hype-first.

Advertising, launch updates, and public messaging should feel like serious company communication rather than generic “save money” SaaS advertising.

## Transparency Policy

AI Call Port should use a transparent public-update model during launch.

This should include:

- clear staged release communication
- public updates on testing progress
- public explanation of changes and improvements
- real timing updates if a stage needs more time

If a stage needs more time, the company should say so openly and provide a new firm date instead of using vague language.

## News And Comment System

AI Call Port should use a public news board as part of the launch trust model.

The news board should:

- share real progress updates
- explain testing and rollout movement
- show what is improving
- help customers and partners understand what is happening

Comments should be allowed as part of the transparency model, but they should be moderated and treated as part of the company’s public communication system.

## Internal Expansion Path

The internal product path remains:

- `Stage A`: AI Call Agent
- `Stage B`: AI Call Agent + Scheduling
- `Stage C`: AI Call Agent + Scheduling + Operational Control

This is the rollout path, not a forced customer path.

## Implementation Priorities

The first implementation block should focus on making Stage A launch-ready as a complete commercial and operational system.

### Block 1: Launch Definition And Activation Rules

- align public pages with Stage A language instead of founder-beta language
- align pricing and offer language around regular plan and partner plan
- add partner-policy agreement into activation flow
- define referral-credit policy in activation and policy docs

### Block 2: Product And Operations Core

- review and finalize Vapi production configuration
- define conversation logic categories
- define uncertainty and fallback rules
- tighten response quality rules
- confirm real call handling behavior across key call types

### Block 3: Customer Setup Logic

- define analysis and configuration layer behavior
- define automatic customer configuration
- define activation and onboarding handoff
- confirm lead -> company -> active customer path

### Block 4: Partner Economics And Dashboard Logic

- implement partner referral links
- implement `$15` active-customer monthly credits
- display referral activity and credits in dashboard
- align billing logic with partner-credit rules

### Block 5: Launch Surface Alignment

- update landing page
- update prelaunch / request page if needed
- update activation pages
- align dashboard messaging with Stage A launch
- remove outdated founder-beta-only framing where no longer correct
- align launch news, transparency language, and community-facing communication with the customer-base + fan-base model

## Immediate Implementation Order

These are the first things that should be done next:

1. Replace outdated founder-beta framing in the launch-facing pages with Stage A launch framing.
2. Add partner-plan agreement into the activation pipeline.
3. Finalize regular-plan and partner-plan pricing presentation.
4. Define and implement partner referral-link and credit logic.
5. Review Vapi production configuration and real call logic categories.
6. Review AI response quality and fallback rules.
7. Review customer configuration and onboarding handoff.

## Launch Standard

AI Call Port is ready for Stage A launch when:

- the public offer is clearly defined
- activation rules are enforceable
- partner plan rules are enforceable
- Stage A call quality is trustworthy
- Vapi configuration is production-ready
- customer setup is repeatable
- referral-credit logic is defined and consistent
- dashboard visibility supports real operations
