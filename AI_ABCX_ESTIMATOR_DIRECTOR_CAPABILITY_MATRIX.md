## 1. Core Rule

`Estimator Director` is not a quote document tool.

It is the controlled estimate-conversion lane inside AI-ABCX:

`request -> estimate preparation -> customer decision -> next operating action`

The difference between levels must therefore reflect:

- workflow depth
- estimate structure depth
- visibility depth
- routing depth
- conversion control depth

If a level does not change those things meaningfully, it is not a real level difference.

## 4. Locked Level Definitions

## Level A

### Business meaning

`Level A` gives the business a real estimate lane with visibility and control.

It means:

- quote requests stop disappearing
- estimate requests can come from real sources
- the business can send professional estimates
- the owner can see what is open, accepted, waiting, or lost

### What Level A must include

- source-aware estimate intake
- standard estimate capability
- estimate request creation from all required launch sources
- estimate state visibility
- customer-facing estimate delivery
- acceptance path
- basic revision visibility
- President estimate visibility
- unresolved estimate visibility

### What Level A does not need to be

- a deep upsell system
- a package-ladder selling engine
- a highly intelligent conversion-control lane
- a fully orchestrated downstream routing system

### Best fit

- owner-led companies
- simpler service quoting
- businesses losing requests through weak visibility
- companies that need quote order before quote sophistication

### Core public story

`We need to stop losing quote requests and send clean estimates with clear visibility.`

---

## Level B

### Business meaning

`Level B` makes estimating more connected and more disciplined.

It means:

- quote handling is not only visible
- quote handling moves through stronger control
- options, revisions, and follow-up become more intentional
- estimate work connects more cleanly to next-step operating lanes

### What Level B must add beyond A

- options estimate support
- stronger revision handling
- stronger follow-up connection
- stronger sales continuity
- stronger accepted-estimate movement toward scheduling
- better source-aware workflow logic
- clearer ownership of unresolved quote paths

### What Level B should feel like in practice

- less quote stalling
- less confusion about what happens next
- cleaner quote backlog handling
- stronger conversion discipline

### What Level B is not yet required to include

- full package ladder logic as a core promise
- strongest executive estimate analytics
- deepest quick-estimate orchestration
- most advanced revenue-lane orchestration

### Best fit

- growing service companies
- businesses with more quote volume
- businesses that regularly revise, compare, or follow up on quotes
- teams where accepted work should move cleanly toward the next operating lane

### Core public story

`We already quote regularly, but we need cleaner workflow, stronger follow-up, and better movement from estimate to next action.`

---

## Level C

### Business meaning

`Level C` makes estimating a major controlled conversion engine.

It means:

- quoting is a serious revenue system
- estimate structure is deeper
- upsell behavior is more intentional
- workflow routing is stronger
- executive and President visibility are richer
- estimate outcomes behave like a managed corporate lane

### What Level C must add beyond B

- package estimate logic
- strongest quick-estimate workflow support
- strongest source-aware routing behavior
- strongest President-level estimate visibility
- strongest connected movement into follow-up, scheduling, sales, and revenue interpretation
- richer accountability around unresolved high-value quote paths

### What Level C should feel like in practice

- quote flow is highly structured
- estimate behavior is operationally managed
- package logic and conversion design are intentional
- the owner can see quote truth as part of a bigger growth engine

### Best fit

- estimate-heavy businesses
- businesses with meaningful sales pressure or quote backlog
- companies where quote conversion strongly affects growth
- teams that want estimate activity to be part of a connected operating system

### Core public story

`Quoting is a major growth lane for our business, and we need the strongest possible estimate workflow, visibility, and conversion control.`

## 5. Capability Adds By Level

This section makes the upgrade logic explicit.

### A -> B must add real capability

The move from `A` to `B` must clearly add:

- options estimate support
- stronger revision path control
- stronger follow-up enforcement
- stronger estimate-to-sales and estimate-to-scheduling continuity
- stronger ownership of unresolved estimates

If those are not materially stronger, the upgrade is not real.

### B -> C must add real capability

The move from `B` to `C` must clearly add:

- package estimate logic
- strongest quick-estimate behavior
- stronger routing and orchestration
- richer President/executive visibility
- stronger estimate-to-revenue operating discipline

If `C` is only cosmetic or analytical, it is not a true `C`.

## 6. Minimum Launch Standard By Level

## Level A launch standard

`A` is launch-ready only if:

- all required intake sources work
- standard estimate works
- send by text, email, and link works
- acceptance path works
- state changes are visible
- President can see estimate truth

## Level B launch standard

`B` is launch-ready only if everything in `A` works and:

- options estimate works
- revision logic works intentionally
- unresolved estimates can hand off cleanly to follow-up logic
- accepted estimates can move more intentionally toward next action

## Level C launch standard

`C` is launch-ready only if everything in `B` works and:

- package estimate works well
- quick estimate path is commercially credible
- high-value unresolved estimate visibility is strong
- estimate lane clearly feels more strategic and more managed than `B`

## 7. Test Gate By Level

## Level A test gate

- website request creates estimate record
- AI call handoff creates estimate record
- manual estimate entry works
- standard estimate sends correctly
- customer accepts correctly
- customer requests revision correctly
- President sees open estimate state correctly

## Level B test gate

- options estimate updates correctly
- revision-request path remains visible and actionable
- follow-up-ready state is created correctly
- accepted estimate moves into stronger next-step workflow
- ownership of unresolved estimates is clear

## Level C test gate

- package estimate presents correctly
- quick estimate works for urgent/repeat path
- strongest source-aware routing behaves correctly
- President/executive estimate visibility is materially stronger than B
- high-value estimate opportunities remain visible and actionable

---

## 8. What Must Not Happen

The levels are wrong if:

- `A` feels locked or fake
- `B` is only a cosmetic upgrade
- `C` is only reporting without workflow depth
- source-aware intake exists only on paper
- acceptance works but downstream handoff does not
- estimate visibility stays trapped inside the estimator surface
